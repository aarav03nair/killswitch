11. World, oracle, scoring

The pretend company the agents work in, how faults are injected, and how the system grades itself against "what would have happened with no fault". Files: world/, inject/, oracle/, score/, bench/.

The world (world/)

This is the application that sits on top of the gateway. It is the part that is specific to the demo.

FileJob
agents.pyTen agents as pure functions: step(agent_id, seed, tick, view, sched) → Action | None. No I/O, no clock, no store. Randomness comes from ks.rng.
tools.pyThe gateway-side tool catalogue (WorldDispatcher). Adapters touch state only through read, put_row, put_plain so the exact touched versions are known.
scenario.pySeed data (seed_state), per-role view scopes (SCOPES), and build_view.
registry.pySupplier master data, customers, SKUs, the attacker IBAN, and the sensitive-field list.
skeleton.pyThe trivial 2-agent scenario (skel.noop, skel.echo) used to test the platform alone.

The ten agents: billing, comms, compliance, crm, docs, intake, inventory, payments, reporter, triage. Example tools: crm.update_supplier, supplier.set_risk_note, payments.send, comms.send_email, docs.write, docs.purge, inventory.adjust.

SeparationAgent processes import world.agents (pure behaviour). The gateway imports world.tools (effects). They never share code paths, so an agent can't call a tool directly.

Faults and the hero scenario

An agent never decides to be faulty on its own. A schedule names the fault, and only the culprit's slot deviates. Fault names in the code: f1, f2, f2plus, f2plus_c, f2plus_x, f3, f4, f7. Culprits: crm for f1, f2, f2plus (and its variants) and f7, comms for f3, payments for f4.

F2+ (the hero), from the docstring in agents.py, with hero tick h:

h crm writes a wrong IBAN h+1 crm writes price x10 on S-22; billing drafts invoice S-17 h+2 payments and comms act on the invoice (outbox items); triage edits an unrelated risk_note h+3 billing drafts an invoice from the bad price (S-22); then the reporter reads the results
VariantWhat it adds
f2plus_xAn honest write-write conflict on the same data. The plan must flag it. A person decides, so R > 0.
f2plus_cThe culprit does honest work between fault and suspension, which gets reverted. C > 0, reported.

inject/spec.py builds an InjectSpec(fault, seed, ticks, t_inject, culprit, variant). t_inject is drawn uniformly in [T/4, T/2] from the seed. A hero guard asserts the precondition that crm stays silent for 10 ticks after the fault, unless the variant says otherwise. RogueSpec is for --rogue runs, where the slot is hostile from tick 0.

The TCB is blindThe gateway gets config.tcb_view(), which strips fault, culprit and fault_tick. The system under test can't cheat by knowing the answer. Only the culprit's process receives KS_FAULT.

The oracle S* (oracle/)

To score recovery you need to know what should have happened. oracle/run.py re-runs the same seed and config with the fault switched off as a "pure world": monitor, containment and recovery are off, and the outbox dispatches at its release tick. It writes an effect ledger (effects.jsonl, with ORACLE_MARKER so it's never confused with a real run).

Then oracle/ledger.py compares real and oracle effects (per table, key and field, plus sink deliveries, values only):

  • B (bad): effects absent or different in S*
  • G (good): effects matching S*, including the culprit's honest writes before suspension

B and G are frozen at the tick recovery starts, the same for the system and every baseline.

Scoring (score/score.py)

MetricMeaning
R (residual damage)Share of B still left at the end. Target 0.
C (collateral loss)Share of G lost. Target 0.
tti_detect, tti_attributeFault → first alert; alert → correct agent and first bad action. Counted in ticks from chained records, never the unsigned alerts file.
ttcAlert → first denied culprit envelope.
post_alert_tainted_effectsTainted effects after the alert. Target 0.
irreversible_tainted_releasedIrreversible tainted effects that left. Target 0.
c_culprit_windowThe culprit's honest work reverted by design.
collateral_stall, fp_cost, false_accusationsCosts of holds, false alarms and wrong blame.
revert_precision / recall, replan_cost, kept_without_redoHow exact the repair was, and how much honest work had to be redone.

A rule worth knowing: an item still held at the end counts as left, so doing nothing scores R = 1. The bench approver releases re-run items in time, so a correctly re-held payment isn't scored as residual damage. Every claim of R = 0 must state how many items the operator released (decision D-17).

The benchmark (bench/, ks bench)

  • Seeds (default 1–20) × faults (default F2+, F2+c, F2+x, F3) × hold windows (0 and 6) × strategies.
  • Strategies: the system, plus the baselines snapshot, revert_culprit_only and no_op. The snapshot and revert-only baselines are labelled oracle-assisted, meaning they're given the fault time, which the real system isn't.
  • Output: median, p95 and max across runs, so a result is a distribution, not a lucky run.
  • An optional contrast run turns the lineage hold off, to show what it buys.
