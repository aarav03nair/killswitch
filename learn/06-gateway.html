6. The gateway (the core)

The reference monitor. Every agent action goes through it, and it decides whether the action runs, is denied, or is held. Main file: gateway/stub.py (483 lines, despite the name). Read this page slowly; it is the platform.

What the gateway is and isn't

  • It decides whether an envelope executes. It does not know what a tool does.
  • It owns the read and write sets, the seq numbers, the transaction, the record and the outbox.
  • It talks to the outside world through three protocols, so the same gateway could front a different domain:
    • ToolDispatcher: classify(env) → ActionClass and execute(env, txn) → Execution
    • ViewProvider: view(agent_id, tick, state) → entries
    • Policy: decide(env, class) → Verdict | None

Its two entry points

Gateway.open(tick, agents)

  1. begin_tick: reset the slot counter and denial counts, prune old nonces.
  2. Seed record (first call only): append record seq 1, a gateway-signed ks.seed envelope whose write set is exactly the initial data. So every state version has a record behind it. Agent actions start at seq 2.
  3. Control phase: admit queued system envelopes (alerts, suspends, approvals, recovery) in a fixed order, capped per tick.
  4. Release phase: for each outbox item whose release tick has come, either dispatch it or hold it (page 7).
  5. Views: ask the ViewProvider for each agent's view. A view sees only seqs below the tick's first seq, so writes made this tick are invisible until next tick.
  6. Return a TickFrame per agent with tick, current epoch and view.

Gateway.tick(tick, frames)

Binds each connection to its agent, sorts frames by agent_id (arrival order is discarded), applies the flood budget, and calls admit on each. Returns replies.

What stops a tool from cheating

  • It can't end the transaction. While the tool runs, a SQLite authorizer denies BEGIN/COMMIT/ROLLBACK. If the transaction is gone afterwards, the gateway refuses.
  • It can't lie about writes. _sets compares the tool's reported write_set with what the store itself holds for that seq (writes_at). A mismatch is refused.
  • It can't lie about reads. Every read must name a version the store really has, with the right hash.
  • It can't touch the outbox. Only the gateway writes outbox:* objects.
  • Any exception is a recorded deny (tool_error). The state transaction is rolled back, but the seq is consumed by the deny record, so there are no gaps.
  • The agent's view entries are merged into the read set, tagged view, while the tool's own are tagged tool.

Why seq is taken first and the record appended last

The state transaction writes versions stamped with the seq, so the seq must exist first. The record is appended after commit. If the process crashed in between, state would hold a write no record explains. ks verify reports that as RECONCILE (compares state_digest(fold(record)) to the live state.db). Not silent.

Control state: gateway/control.py

  • FoldedControl is the agent state, computed as a fold over the executed ks.control records. So status and epoch are derived from the chain, never from a hidden variable.
  • EpochFold: epochs are strictly monotonic (rule D1). Suspend, revoke and release each take next_epoch = max + 1.
  • check() runs before a control is recorded and apply() after, so the control state never runs ahead of the chain.
  • A revoked agent can't come back. Release requires the agent to be suspended.

System envelopes: gateway/system.py

The monitor, operator, recovery service and the gateway itself submit signed system envelopes on connection c-0, admitted by admit_system. Differences from agent admission: no frame-tick, control or class steps, and scope is inverted: the principal must be a registered signer of that tool. Served tools: ks.alert, ks.approve, ks.control, ks.recover.*, plus gateway-internal ks.seed and ks.dispatch. They are queued in a SystemQueue and admitted at the next open, in a fixed order.

Holds: gateway/holds.py

  • hold outbox:<id>: a queued item becomes held, via a recorded control.
  • unhold outbox:<id>: back to queued. The next release phase re-checks taint before dispatching.
  • unhold action:<record id>: re-executes a held agent action once, through the normal transaction. The record carries reexec_of pointing at the hold. Nonce and expiry aren't re-checked.

Policy seam: gateway/policy.py and policy/

The gateway only defines Policy.decide and runs it at step 12 (AllowAll by default). The world's rules live in policy/__init__.py:

  • p.scope: tool or table outside the role → deny/out_of_scope (e.g. only crm may call crm.update_supplier).
  • p.i2_approval: I2 → hold/needs_approval.
  • p.i1_outbox: I1 is admitted, and the outbox enqueues it.
  • Read scope: every table a tool reads must be in the role's view tables, except the row it reads in order to modify it.
  • The policy sees the envelope only, never raw state. Lineage and taint holds are the outbox's job.
