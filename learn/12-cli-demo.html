12. CLI, demo, console

How you drive it. cli/__init__.py defines the ks command, scripts/demo.sh strings it into the demo, and console/ renders the incident view.

Commands

ks runRun agents through the gateway and write a run directory. Options: --scenario skeleton|world, --agents, --ticks, --seed, --key-mode fresh|repro, --tick-deadline-ms, --run-id, --shared-uid, --out, plus --pause-at, --step, --pause-on-alert.

The CLI returns its own usage code (64) rather than argparse's 2, and uses the contract Exit codes elsewhere.

The live operator loop

With --pause-at, --step or --pause-on-alert the gateway pauses between ticks. The operator talks to the running gateway over a local socket (runtime/operator.py, peer-credential checked), so a human decision enters the chain as a ks.operator-signed record, not a side channel.

What scripts/demo.sh does

  1. Builds the image if needed, then starts a detached container (no network) running ks run --scenario world --fault F2+ --seed 2 --ticks 40 --pause-on-alert. Seed and ticks are overridable with SEED and TICKS.
  2. The fault lands, the monitor alerts, and containment suspends the culprit. The run pauses before the tick after the suspend (the operator beat).
  3. ks recover RUN --dry-run prints the plan and a plan id (p-…).
  4. ks recover RUN --apply p-… applies it. The output lists outbox items to release.
  5. The script runs ks contain unhold outbox:ob-… for each listed item, then sends a resume.
  6. The container exits. The script reads the RunAnchor from the log.
  7. ks verify --head ANCHOR RUN checks the run, ks score RUN writes the scorecard, and ks console RUN --html … renders the incident page.
  8. A final check asserts verify exit 0, anchored true, and prints the isolation mode.
Make targetsmake demo runs this script. make smoke is the small 2-agent anchored check. make test runs pytest in the container with --network none.

The console (console/)

Read-only. model.py builds a model of the incident from the run directory alone (BEATS: the five story beats), html.py renders it to static HTML, and live.py shows it in the terminal, optionally stopping at each beat (--pace). It derives everything from the chained records, so the console can't show anything the evidence doesn't support.

Running things yourself (suggested)

make test        # full suite in the container
make smoke       # 2 agents, 10 ticks, anchored verify
make demo        # the hero path; open the printed console HTML
ks verify --json --head "$ANCHOR" runs/<id>
ks bench --seeds 1-5 --faults F2+ --hold 6     # a quick look at the benchmark

I haven't run these commands for this course. Natively on macOS isolation is degraded, so use the container for anything about attribution.
