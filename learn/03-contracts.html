3. Contracts: the shared language

src/ks/contracts/ defines every message and document in the system. Learn these shapes first and the rest of the code reads easily.

The envelope (C1)

An agent's request. The agent builds it, the signer signs its header, and the gateway verifies it.

Envelope(agent_id="crm", action_id="crm-7", parent_action_id=None, act_chain=(),
         tool="crm.update_supplier", args={...},
         nonce=<random 32 hex>, expiry_tick=tick+2, epoch=current_epoch,
         claimed_ts_us=None, claimed_seq=None, sig=None)
  • agent_id, action_id: who, and a unique id for this action.
  • nonce, expiry_tick: stop replays. A used nonce is refused, and an envelope past its expiry is refused.
  • epoch: the agent's "generation". Suspending an agent bumps it, so old pre-signed envelopes die (see page 9).
  • act_chain: if an agent acts on behalf of another, the chain of principals. If any ancestor is suspended, the action is denied.
  • claimed_ts_us, claimed_seq: agent claims about time and order. They are never trusted. The gateway assigns the real seq and time.
  • header vs args: the signed header holds args_hash, not the raw args. If the args don't hash to args_hash, that's bad_sig (a spliced-args attack).

The record (C2)

One record is written for every envelope the gateway receives, executed or not.

Record: seq, record_id, prev_hash, hash, gw_sig,        # the chain + gateway signature
        tick, ts_us, conn_id,                           # gateway-assigned
        envelope (header), envelope_hash, sig_ok,
        decision (exec|deny|hold), reason, policy_rule,
        action_class (R|C|I1|I2|U),
        read_set, write_set, outbox_ids, result_hash,
        control, reexec_of
  • prev_hash + hash chain the records. Changing any old record breaks every later hash.
  • read_set lists versions the tool read plus every view entry delivered to the agent that tick. Entries are tagged source=view|tool.
  • write_set gives before and after version and hash for each object written.
  • No raw values appear in a record. They sit in the side store, keyed by hash.

One serializer, so hashes agree

contracts/canonical.py is the only encoder the signer, gateway, recorder and verify may use. Rules: sorted keys, UTF-8, no whitespace, integers only (no floats), no bytes, nesting depth at most 32. Every decode failure is a CanonicalError, which the gateway turns into deny/schema. A test greps the source for stray json.dumps.

signing_bytes() = DOMAIN_TAG + 0x00 + canonical(doc without sig/hash fields)
content_hash()  = sha256(signing_bytes)
Why domain tags?Each type has its own tag (ks/envelope/v1, ks/record/v1, and so on), so a signature made for one kind of document can't be replayed as another.

Other things defined here

  • Object ids (state.py): table:pk for a row, and table:pk.field for a sensitive field that is its own object.
  • System principals (ids.py): ks.gateway, ks.monitor, ks.operator, ks.recovery. They act on the special system connection c-0, never on an agent socket.
  • RunDir (rundir.py): file names and how the run directory is laid out and chowned.
  • Exit codes (Exit): what ks verify and others return.
