Learn the Kill Switch gateway

A guided course through the code. By the end you should be able to explain how an agent action travels through the system, why the record can be trusted, and how one agent's damage is undone.

How to use thisRead the pages in order. Each page says what a part is, why it exists, how the code does it, and which files to open. File paths are relative to src/ks/ unless they say otherwise. Everything here comes from reading the code and its docstrings, and I haven't run it for this course.

The idea in four sentences

  1. Agents don't touch shared data. They send signed requests to one gateway.
  2. The gateway checks each request, runs it inside a database transaction, and writes a tamper-evident record of exactly what was read and written.
  3. Because every read and write is attributed, "who did it" and "what depended on it" become lookups.
  4. That makes containment (stop one agent) and recovery (undo only its damage and what it infected) possible.
