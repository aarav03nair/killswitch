# CON-02: contract change requests (contracts 1.0.0 → next)

Collected requests against `src/ks/contracts/`. Any field, enum or validator change bumps `CONTRACTS_VERSION` and regenerates `schema/`. SEC-03 ids (B1–B4, F1–F8, N1–N10) refer to org/reports/SEC-03.md.

## from maya review

19 Nov · maya · Sources: ADR-00 (own), reviews of ADR-04, ADR-05, ABS-04 and SEC-02.

### Field, enum or validator changes (version bump)

| # | Contract | Change | Why / source |
|---|---|---|---|
| M1 | C2 `WitnessCheckpoint` | Add `count: NonNeg`, signed, strictly monotonic per run. No-op ticks repeat `(seq, head)` with a new `count` | ADR-00 witness cadence, THREAT-MODEL v3 `(seq, head, tick, count)`. Same as SEC-03 B1(a) |
| M2 | C6 `RunConfig` | Add `fault_tick: Tick \| None` (t0). It is set iff `fault` is set (extend the `fault`/`culprit` validator). | M3 | C4 `Alert` | Allow empty `evidence_seqs` only when `kind == anomaly` and `detector == "barrier.deadline"`. Such an alert may name the agent that missed the deadline in `root_candidates` (it is never hard) | ADR-00. A missed tick barrier is a no-op, and no-ops create no record, so there is no seq to cite |
| M4 | C4 `ControlOp.RELEASE` / gateway rule | Per-target epochs are **strictly monotonic**. `suspend`/`revoke`/`release` on an agent always set an epoch greater than every earlier one. Docstring: "release sets a fresh epoch; never reuses the pre-suspend one". README: "release = un-hold + restore epoch" means "the agent is active again at a fresh epoch" | ADR-04 §6 says "restoring the pre-suspend epoch", which revives presigned envelopes (RT4, RT5). | M5 | Transport `TickFrame` | Add `epoch: Epoch | None`, the current epoch of the connection's principal (`None` while suspended or revoked) | After a release the agent has no way to learn its fresh epoch (TickFrame carries only `tick`), so a released honest agent would be denied `stale_epoch` forever. This breaks RT11's "release restores the victim" |
| M6 | Transport `TickFrame` + C2 read-set rule | **Define the agent view.** Proposal: add `view: tuple[ViewEntry{obj, ver, hash, value}, ...]` to `TickFrame`. The gateway chooses it from the scenario's per-agent read scope (ADR-06 table) and adds the delivered entries to the `read_set` of the record for whatever that agent submits in that tick. The gateway captures this; the agent never declares it. Noop ticks create no record and need nothing | ADR-06 defines agents as `f(seed, tick, view)`, but no contract carries `view`. A deterministic agent's decision inputs (crm reading `tickets:T-3`) never appear in any read set. Then ADR-05 forward taint under-taints and RT9 backward taint cannot reach intake. **Blocker for ADR-05 and RT9**; decide at freeze |
| M7 | C4 `Alert` (validator) / `HARD_ALLOWED` | `kind ∈ {tamper, witness_stall}` ⇒ `hard = False`, and drop both from `HARD_ALLOWED`. The recovery freeze is automatic by kind, not by `hard` | ADR-02 and ADR-04 disagree. Adopting SEC-03 N4 |
| M8 | C2 `Reason` | Add `STALE_PLAN = "stale_plan"` to `REASONS_FOR[HOLD]`. Use it for a `ks.recover.*` step whose `expect` is no longer the head; `needs_approval` stays for I2 and approvals | vikram's optional ask (ADR-05), **accepted**. Without it the console and `replan_cost.approvals` (ADR-06) cannot tell a stale plan from an I2 approval |
