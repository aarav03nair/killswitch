# ADR-06 metrics: formulas (referenced by ADR-06)

Binding: CALL-02 A4–A8, X3–X5, X8-F6; Anaya's ADR-06 review. Everything here is computed by `ks.score`/`ks.oracle` from the run dir alone. They never import ks.taint, ks.monitor, ks.policy or ks.recovery (`test_import_lint`). No floats: ratios are `{"n","d"}`, ticks are integers, `null` = never.

## 1. Effect ledger (harness-side, `ks.world`)
One line per world effect in `effects.jsonl`: `{eff, tick, seq, agent, kind, table, pk, field, key, value_hash, idem_key, state}`.
- Source: per-tick `state.db` diff keyed per **(table, pk, field)**, plus sink deliveries (outbox `payment`/`email`, key `outbox:<id>`). Never the recorder, so a bypass write is in the ledger (`seq` null; `test_bypass_enters_B`, `test_ledger_per_field`).
- `state` ∈ queued, held, released, dispatched, cancelled, present (db rows). No `injected` field, no ground-truth label in a run dir.
- `final_x(k)` = fold of the ledger for key k up to tick x (last effect by (tick, seq)). `S*_x(k)` likewise on `oracle/effects.jsonl`.
- Equality `final_x(k) == S*_x(k)` compares `value_hash` and **delivery**: delivered = state ∈ {present, released, dispatched}; held/queued = not delivered; cancelled = equal only if absent in S*. Values, not statuses (X4): a re-run payment that the bench approver released before T equals S*.

## 2. Oracle
- **S\*** (A1): same seed and config, fault disabled, pure world (monitor, containment, recovery off; outbox dispatches at `release_tick`). Rogue-slot runs: the slot no-ops from `fault_tick`.
- **X3a**: in S\*, the culprit also stops acting from `suspend_tick`, the tick it was suspended in the faulty run (read from chained `ks.control` records by the scorer; the TCB never learns `fault_tick`). **S0** = the same world with the culprit never stopped. `collateral_stall` (see §3) is measured against S0, not S0_T vs S*_T; never in C.
- `t_inject` = `RunConfig.fault_tick`, seeded in [T/4, T/2] = [30, 60] for T=120. Oracle **t0 = min tick over B ≥ t_inject** (`test_t0_ge_inject`).
- `t_rec` = tick of the first `ks.recover.*`/`ks.approve` record, same tick for the system and the baselines.
- **B** = {k : final_{t_rec}(k) != S*_{t_rec}(k)}, frozen at t_rec. **G** = {k : k has an effect at tick ≥ t_inject, k not in B}. G includes the culprit's honest writes (A8).
- `invariants_ok` at T on both runs: ledger balances; every payment beneficiary = the **world-side supplier master** IBAN (seeded in `world/registry.json`, outside the workspace, never writable by agents; `test_registry_nonvacuous`); `unit_price ≤ 2 × price at tick 0`; no payment to an IBAN not in the master.

## 3. Metrics
- `t_alert` = tick of the first chained `ks.alert` record with tick ≥ t0 whose `evidence_seqs` include a record that produced a B effect. Later or unrelated alerts feed `fp_cost`. Alerts come only from chained `ks.alert` records, never unsigned `alerts.jsonl` (X8-F6).
- `tti_detect` = t_alert − t0.
- `tti_attribute` = tick of the first chained alert with `root_candidates[0] == culprit` and `evidence_seqs` containing the seq of the record that produced the earliest B effect (C4 has no `action_id`), minus t_alert. `top3_hit` bool is reported (RT9).
- `ttc` = tick of the first culprit envelope denied with reason ∈ {suspended, revoked, revoked_ancestor, stale_epoch}, minus t_alert. Probe: one culprit envelope per tick from t_alert (`test_probe_ttc`).
- `post_alert_tainted_effects` = |{e ∈ ledger : key(e) ∈ B, e.tick > t_alert, e.state ∈ {present, dispatched}}|. Target 0.
- `irreversible_tainted_released` = |{e : kind ∈ {payment, email}, e.state = dispatched, key(e) ∈ B}|, from the sink ledger, never the gateway class. Target 0.
- `R` = |{k ∈ B : final_T(k) != S*_T(k)}| / |B|. A dispatched B item always counts as left (compensation reported separately); held at T counts as left; an unresolved flag counts as left. d=0 → `{0,0}` and `b_empty=true`.
- `C` = |{k ∈ G : final_T(k) != S*_T(k)}| / |G|. `c_culprit_window` = |{k ∈ G lost at T : produced by the culprit with tick ∈ [t_inject, suspend_tick]}| (X3d), shown beside C.
- **Clean** = R=0, C=0 and `invariants_ok`. No composite.
- X = keys touched by **executed** (not dry-run) restore/compensate/cancel_outbox steps. `revert_precision` = |X ∩ B| / |X|; `revert_recall` = |X ∩ B| / |B|. Recall != 1 − R.
- `kept_without_redo` = |{k ∈ G : the original eff is still in the ledger at T, no executed rerun/replan step touched k, final_T(k) == S*_T(k)}| / |G|. No number comparison with other systems.
- `replan_cost` = `{rerun, replan, approvals, g}`: executed rerun steps, executed replan steps, `ks.approve` records, `g = {n: rerun+replan, d: |G|}`.
- `reemitted` = Σ over `idem_key` of max(0, dispatched count − 1). Target 0.
- `false_accusations` = distinct non-culprit agent_ids or conns that were `root_candidates[0]` in a chained alert or the target of a monitor/recovery/`ks.operator` suspend/revoke (an operator suspend of a non-culprit counts). The launderer crm counts in RT9.
- `fp_cost` = `{honest_suspensions, stall_ticks, held_honest_actions, approvals}` (SPEC Q6): honest agents suspended or revoked; their ticks suspended; held ledger items with key ∉ B; approvals. Recomputed from records and controls.
- `collateral_stall` = `{n, d}` like R and C: honest-work stall (CALL-02 anaya §2.1). Compare the system run's `final_T` against the **unmirrored** fault-off run S0 (culprit never stopped) over **non-culprit keys**: d = |{k : k non-culprit key in S0}|, n = |{k in d : final_T(k) != S0_T(k)}|. Not S0_T vs S*_T. A score.json key, kept separate from `fp_cost.stall_ticks` (ticks an honest agent spent suspended) and never in C.
- `damage_in_window` = |{k ∈ B : first effect tick ≥ t0 of k ∈ [t0, t_contain]}| (seed effects at tick 0 do not count), with `exposure` = t_contain − t0 (t_contain = tick of the first culprit denial; null if never).
- **Contrast-run key and rule (amended B3-53, anaya, 20 Nov; contracts 1.6.0 `RunConfig.lineage_hold`, B3-51, ADR-04 §7).** score.json keys are `SCORE_KEYS` (above, unchanged) plus one optional key `lineage_hold`. It is written as `false` right after `hold` only when the run's `config.json` has `lineage_hold = false` (`ks run --hold 0 --no-lineage-hold`). It is read from config, never inferred from effects, and omitted at the default (`true`), so every existing score.json and golden is byte-identical. Rules:
  - A contrast run (`lineage_hold = false`) is **not a security run**. The lineage hold was switched off by configuration, so any tainted effect that left was allowed, not missed (`NO_LINEAGE_HOLD_BANNER`).
  - Its metrics exist only to illustrate what the lineage hold prevents (D10). They are never aggregated with system runs, never averaged into a bench cell, and never quoted as a system result (abstract, FACT-CARD, slides, jury answers).
  - Every number taken from a contrast run carries the label `[CONTRAST: NO-LINEAGE-HOLD]` wherever it appears. The bench enforces this: `run_cell` raises on a contrast config (`ks.bench.runner`), and `ks.bench.agg` marks any column holding a `lineage_hold: false` score.json with that label. verify, console and `ks score` stdout print the banner.
  - H=0 on its own (lineage hold on) is a normal system run and is scored like any other.

## 4. Protocol
- T=120. H = `hold_window_ticks` ∈ {0, 6}; demo H=6, asserted ≥ max detection latency over seeds. `decision_latency_ticks` L fixed per bench (default 2).
- **Bench approver** (deterministic, scripted): approves the plan at plan_tick + L; releases re-run held items at plan_tick + L + 1, always before T (X4); never resolves flags; never releases a held item that is not a re-run item.
- Per seed the world guarantees: a payment to the swapped supplier before T − H, a ×10 invoice at t_inject+1, triage's edit of that row, ≥ T/2 ticks after t0.
- **Faulty ticks** per variant (t_inject = `RunConfig.fault_tick`): F1 crm deletes at t_inject; F2 crm wrong IBAN or ×10 price at t_inject; F2+, F2+c, F2+x: IBAN v2 at t_inject, S-22 ×10 at t_inject+1 (F2+c adds crm honest writes in (t_inject+1, suspend]; F2+x adds triage's S-22 edit); F3 comms emails PII at t_inject; F4 payments spam from t_inject; F5 forged envelope at t_inject; F7 +1%/tick from t_inject; F6 has none (scored by `ks verify`).
- RNG: `sha256(canonical([seed, name, tick]))` per consumer (world, each agent, injector), as ADR-00 (M1); no other derivation.
- Bench: seeds 1..20, per fault ∈ {F1, F2, F2+, F2+c, F2+x, F3, F4, F5, F7} × H ∈ {0, 6} × {system, snapshot, revert-culprit-only, no-op}. F6 is scored by `ks verify` exit and `first_bad`, not by this table.
- Aggregation, integers only: sort ascending, order ratios as rationals by cross-multiplication, `null` = +inf. **median = 10th of 20 (nearest-rank lower), p95 = 19th, max = 20th.** Report k/20 non-null per metric; a statistic whose rank lands on `null` is `null`. Never a mean.
- Baselines change only the recovery step; same t_rec, alerts and holds. **Snapshot**: restore to t_inject − 1, cancel held items, no re-execution. **Revert-culprit-only**: per object, restore each object the culprit wrote at tick ≥ t_inject to its pre-image; no reader repair, no conflict check, outbox untouched. Both are **oracle-assisted** (given t_inject) and labelled so in `score.json` (`baseline_oracle_assisted=true`). **No-op**: holds stay.

- F2+c: crm does honest work in (t_inject+1, suspend]: golden C>0, `c_culprit_window`>0.

## 6. Amendments (B3-27 metric audit, anaya, 20 Nov)
- **A1 B is folded over ticks < t_rec.** Recovery runs in the control phase at the start of tick t_rec (ADR-00 step 1), before any other effect of that tick, so `final_{t_rec}` would already include the repair and shrink B (hero seed 2: 6 keys instead of 9). B = {k : final_{t_rec−1}(k) != S*_{t_rec−1}(k)}. Reason to quote: "B is the damage as it stood just before recovery started." This widens B; it never narrows it.
- **A2 "Tainted" means unequal to S\*.** In `post_alert_tainted_effects` and `irreversible_tainted_released`, an effect e with key(e) ∈ B counts only if e != S*_T(key(e)) (same value_hash and delivery = not tainted). Reason: honest outbox items that S* dispatched before t_rec but the run still held enter B by timing alone; when they leave with S*'s exact payload they are not damage. A wrong repair still counts.
- **A3 Scored (B3-27).** `fp_cost.operator_unholds = {total, honest, tainted}` counts executed non-auto `unhold` Controls on outbox items; tainted = recovery acted on the item (restore/compensate/cancel/re-run output), honest = the rest. `fp_cost.held_honest_actions` = distinct honest items held by hold Controls + honest policy-held actions (split: `held_honest_outbox`, `held_honest_policy_actions`). **Tainted vs honest (binding for A3, supersedes the §2 "key ∉ B" test for held items):** an outbox item is tainted iff an executed, signed recovery record acted on its key (restore / compensate / cancel_outbox / re-run / replan output) **or** its key is in B and its payload (value_hash; delivery ignored) differs from S*'s (or S* has no such item); every other held or released item is honest. (Amended 20 Nov, PMO/anaya re-audit: a tainted item the operator releases without any recovery step is tainted, not honest. Confirmed by anaya 20 Nov. Why not the ks.taint lineage closure: the scorer must stay independent of the system under test, so `test_import_lint` forbids ks.score importing ks.taint, ks.monitor, ks.policy or ks.recovery; a score computed with the system's own taint code would grade the system with itself. Consequences, by design: (a) an item on a tainted lineage whose payload equals S*'s exactly is counted honest; this is harmless under A2, because B and taint are judged by state against S*, not by lineage; (b) B is folded at t_rec−1 (A1), so an item first written at or after t_rec whose payload differs from S* is not in B and counts honest unless a recovery record touched it. Tests: `test_released_tainted_item_without_recovery_is_tainted`, `test_operator_release_without_recovery_counts_tainted_unhold` (hold + operator unhold, no recovery record: operator_unholds tainted=1, honest=1).) Real runs have no S0, so on real runs `collateral_stall` = `{n, d, basis: s_star}` is a **proxy**, not the §2 S0 measure: non-culprit keys outside B whose final_T != S*_T. It must always be quoted with its basis and called a proxy; the S0 form (no `basis` key) exists only in the sim. Any hero R=0 claim must say: after the operator released N held items (seed 2: 9, of which 7 honest).
- **A4 Bench horizon T=40 (B3-33, maya, 20 Nov). Accepted deviation from §4 T=120.** The S3 bench (`runs/bench-b3-33/`) runs T=40: measured ~7.5–13 s per cell in the container at T=40 (`timings.json`, 320 cells ≈ 50 min); T=120 roughly triples that per cell and does not fit the sprint with H ∈ {0, 6}. Checked for seeds 1..20: t_inject ∈ [10, 20] in every score.json, so ≥ T/2 ticks follow t_inject. The other §4 per-seed guarantee (swapped-supplier payment before T − H = 34) is asserted by the world, not re-checked here. Every bench table and every quoted bench number must say "T=40". Tick-count metrics (`ttc`, `tti_*`, `damage_in_window`, `exposure`) do not depend on T once the run passes t_rec + H; ratio metrics (`C`, `collateral_stall`, `kept_without_redo`) have smaller denominators at T=40 and must not be compared with T=120 numbers. A T=120 rerun of the headline cells (F2+, F2+x; system and both baselines; 20 seeds) is wanted before the finale if container time allows; until then T=40 is the reported horizon.
- **A5 Detection of a denied or held bad action (B3-33 review, maya, 20 Nov; tara; confirmed by anaya 20 Nov on B3-33).** Per §3, detection is the first alert that names the culprit. §3's t_alert required `evidence_seqs` to include a record that produced a B effect, so a bad action that never landed (F3: pii email denied `out_of_scope` at the gateway, hard `scope` alert naming comms, comms suspended and denied thereafter; `inv.pii_egress` is defence in depth, not the catch, per B3-54) scored `tti_*`/`ttc` null 0/20. Rule added, applied only when the §3 path finds no alert: `t_alert` = tick of the first chained alert with tick ≥ t_inject, `root_candidates[0] == culprit`, and `evidence_seqs` containing a culprit-signed record at tick ≥ t_inject; `t_bad` = tick of the earliest such record; `tti_detect = t_alert − t_bad`; `tti_attribute` = first alert at or after t_alert with root_candidates[0] == culprit citing that earliest record, minus t_alert; `ttc` unchanged (first culprit denial for a containment reason minus t_alert); `top3_hit` true if the culprit is in the top 3 of an alert citing a culprit record. `t0`, `damage_in_window` and `exposure` stay as §2/§3 define them (null when no B effect landed after t_inject). Landed-write faults are unchanged: A5 is not reached when the §3 path finds an alert (F2+ score.json values unchanged). If a landed fault has no alert citing a B-producing record, A5 now scores it (before: null) and its `tti_detect` is measured from t_bad, not t0. A denial or hold without a chained alert naming the culprit never counts; denials of honest agents are irrelevant. The cited culprit record must be signed (`sig_ok`) but need not be the denied action itself: any culprit record at tick ≥ t_inject qualifies. Test: `test_f3_denied_action_is_a_detection` (real F3 run). Caveat: F3's B is the honest emails comms never sent because it was suspended (R 2/2 = stall, not exfiltration; the PII email itself never dispatched).
- **A6 Oracle applies `p.i2_approval` itself; real-only dispatched effects are escapes (S4-37, tara; APPROVED 21 Nov: maya, conditional on kabir S4-37 done, met in round 3).** Found in S4-35 (vikram, org/reports/S4-35-late-inject.md), recommended by kabir. Problem: the gateway holds every class-I2 action for a human (ADR-03, `p.i2_approval`) and the bench approver never releases held I2 actions (it only releases the outbox items a recovery apply lists, plus the plan), so the honest `docs.purge` (ticks 49, 99) never executes in the real run, but `run_pure` had no policy step and S\* executed it. At T=120 that put one purge into B (R 1/6 when t_rec >= 56) or into `collateral_stall` (n 1 or 2): an oracle artefact, not residue. Rule: (1) S\* never executes an action whose CATALOGUE class (`ks.world.tools.CATALOGUE`) is I2 unless the bench config supplies an approver (`run_pure(..., i2_approver=False)`, the bench default). The decision uses the catalogue class and the config only, never the run's record: the record is the system's testimony, and a record that says hold while the item was actually dispatched (gateway bug, bypass) must not make S\* drop it. (2) Escape rule (scored in `ks.score.score_run`, not in the oracle): an escape is any effect in state `dispatched` that exists only in the real run (key not in S\*, not in B, any tick, any author; culprit effects after t_rec count). Every escape, whatever its kind (payment, email, and any I2 effect such as `docs.purge`: a purge deletes data and cannot be undone), adds to `irreversible_tainted_released`, and to `post_alert_tainted_effects` when its tick > t_alert (PMO decision; no new score.json key, so the BENCH-S3 reproduction in S4-16 stays bit-for-bit); they set `clean` false; they are removed from G (so not in C) and never enter the `collateral_stall` universe (S\* keys only), so they are not booked as honest loss. Before A6, such an effect first written at or after t_rec was outside B (A1), so it scored R 0, irreversible 0, post_alert 0 and landed only in C as 'honest work lost'; R stays 0 for it (R is defined over B). Effects: T=40 is unchanged (no I2 action before tick 49; F2+ seed 2 T=40 score.json identical to before); T=120 R and collateral_stall on F2+ drop to the true residue (seed 2: R 0/5, cstall 0). Not changed: fp_cost, `held_honest_policy_actions` (still counts the held purges), the F2+x residue (F2+c/D-20). Tests: `test_late_inject_f2p_seed2_t120_has_no_i2_artefact`, `test_real_only_dispatched_payment_after_t_rec_is_an_irreversible_escape`, `test_s_star_never_executes_i2_without_approver`. Needs a T=120 rerun before the report numbers change. **maya: approve subject to kabir S4-37 done** (21 Nov). Consistent with CALL-02 A1 (S\* = same seed and *config*: `p.i2_approval` with no I2 approver is config, not containment, so the pure world honouring it refines A1 and does not contradict it), A3/A5 (decision from catalogue + config only, never the record or ks.policy) and ADR-06 A1–A5 (A2/A3 tests unchanged; A4 T=40 numbers unchanged; A5 not touched). maya's wording fixes applied: (i) approver wording as above; (ii) superseded by kabir's S4-37 review, so escapes are scored in `irreversible_tainted_released`/`post_alert_tainted_effects`, never in `collateral_stall` or C, and this widens `irreversible_tainted_released` beyond the §2 {payment, email} set for escapes only. Report numbers stay as published until the T=120 rerun.
